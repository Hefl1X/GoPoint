# Запросы для Claude Code: «GoPoint»

## Как это устроено

Правила проекта лежат в файле `CLAUDE.md` в корне папки. Claude Code читает его в начале каждой сессии, поэтому в самих запросах правила не повторяются: они короткие и содержат только задачу и условие готовности.

Три принципа:
1. **Один запрос равен одному результату, который вы проверяете сами** на телефоне или в браузере. Не переходите дальше, пока не проверили.
2. **Технические решения Claude Code принимает сам.** Он спрашивает вас только про деньги, поведение продукта для пользователей, данные с чужих сайтов, удаление, публикацию (список в `CLAUDE.md`).
3. **После каждой задачи Claude Code присылает короткий отчёт для вас по-русски:** что получилось, как проверить без кода, что решил сам, что нужно от вас.

Как начать: создайте папку проекта, положите в неё `CLAUDE.md`, откройте Терминал на Mac, перейдите в папку и запустите `claude`. Установка Claude Code описана в официальном руководстве (code.claude.com/docs, раздел Quickstart): способы установки менялись, опирайтесь на актуальную страницу.

### Если закончились лимиты или сессия оборвалась
Всё важное лежит в файлах проекта и в git, а не в переписке: после каждой задачи Claude Code обновляет `docs/HANDOFF.md` и делает коммит. По документации Claude Code, при долгой переписке контекст сжимается и подробные инструкции из начала могут потеряться, поэтому после перерыва вставьте **Запрос А**: он заставляет заново прочитать правила и состояние из файлов. Продолжить сессию можно командами `claude --continue` или `claude --resume`, либо просто запустить `claude` заново. Проверьте названия команд через `claude --help`: интерфейс меняется.

## Запросы на каждый день

### Запрос А. Начало сессии или продолжение после перерыва

```text
Начинаем или продолжаем работу. Не опирайся на память о прошлой переписке, восстанови контекст из файлов:
1. Прочитай CLAUDE.md, docs/ARCHITECTURE.md, docs/HANDOFF.md, docs/DECISIONS.md.
2. Выполни git status, git diff --stat, git log -15 и запусти все проверки.
3. Если есть незакоммиченные изменения, определи: законченная работа, начатая работа или мусор. Не откатывай и не коммить без моего слова.
4. Сверь HANDOFF.md с реальным состоянием кода и скажи, если они расходятся.
5. Скажи по-русски в 5 строках: что сделано, на чём остановились, что сломано, что делаем дальше. Дальше сразу берись за следующий шаг из HANDOFF.md, если он не требует моего решения.
```

### Запрос Б. Срочное сохранение (когда чувствуете, что лимит близко)

```text
Сохрани состояние так, чтобы продолжить без этого чата: запусти проверки, обнови docs/HANDOFF.md (что сделано, где остановились: файл и шаг, что дальше, вопросы ко мне, известные баги, как запустить), допиши решения в docs/DECISIONS.md, закоммить (незаконченное, но не ломающее сборку, с префиксом wip:). Если сборка сломана, не коммить в основную ветку, а опиши проблему в HANDOFF.md. Скажи мне в 3 строках, что сохранено.
```

### Запрос Г. Разбор бага

```text
Баг: <что вижу, на каком экране, на каком телефоне и браузере, что ожидал>.
Сначала найди причину и объясни её простыми словами. Потом напиши тест, который воспроизводит баг и падает, исправь минимальным изменением, убедись, что тест и все проверки проходят. Проверь, нет ли такой же ошибки в других местах. Если причина в архитектуре, скажи отдельно. Дай отчёт по формату из CLAUDE.md.
```

## Основная последовательность

Порядок построен так, чтобы после каждого запроса вы могли что-то проверить сами. Схема, стек и структура репозитория лежат в `docs/ARCHITECTURE.md`: Claude Code читает её в начале каждой сессии.

