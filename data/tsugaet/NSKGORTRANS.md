# Данные сайта ЦУГАЭТ (map.nskgortrans.ru): анализ и утилита

Этот комплект самодостаточный: он не зависит от прошлого проекта. Он для человека и для ИИ-агента, которые начинают проект с нуля (например, PWA с картой низкопольного транспорта Новосибирска).

ЦУГАЭТ (МКУ «Центр управления городским автоэлектротранспортом», мэрия Новосибирска) разрешил брать данные с сайта и пообещал позже прислать полные данные. Перед запуском лучше получить это разрешение письменно.

> **Официальной документации у ЦУГАЭТ нет.** Всё ниже выяснено 2026-11-04 по коду их сайта и по ответам сервера. Код сайта: `config.js`, `main.1.3.min.js`, `lib.js`, `myknockout.js`, `raps.min.js`.
>
> Пометки:
> - **[проверено]** — видели в ответах сервера;
> - **[догадка]** — следует из кода или наблюдений, но ЦУГАЭТ этого не подтверждал.
>
> Сайт могут поменять без предупреждения. Поэтому первым делом запустите `check` (ниже).

## Что в папке

| Файл | Что это |
|---|---|
| `NSKGORTRANS.md` | этот файл: все адреса, поля, ловушки, советы для PWA |
| `nskgortrans.py` | утилита командной строки и библиотека разбора. Нужен только Python 3.9+, без внешних пакетов |
| `samples/*.json` | настоящие ответы сайта от 2026-11-04: образцы для тестов разбора |

## Быстрый старт

```bash
python3 nskgortrans.py check                                        # формат сайта не поменялся?
python3 nskgortrans.py routes --type tram                           # маршруты (с ключом r)
python3 nskgortrans.py vehicles --route 3 --type bus --low-floor    # низкопольные машины автобуса 3
python3 nskgortrans.py vehicles --route 3 --type bus --raw          # сырой ответ сайта
python3 nskgortrans.py trace --route 13 --type tram --direction B   # остановки по порядку
python3 nskgortrans.py forecast --stop 76                           # прогноз на остановку
python3 nskgortrans.py snapshot                                     # обновить samples/
python3 nskgortrans.py --help                                       # все команды
```

Как работает утилита:
- результат печатается как JSON в stdout, ошибки идут в stderr с кодом выхода 1;
- виды транспорта: `bus`, `trolleybus`, `tram`, `minibus`;
- `--route` всегда указывайте вместе с `--type`: номера маршрутов повторяются у разных видов (есть автобус 13 и трамвай 13);
- между запросами утилита делает паузу 0,5 с (в `snapshot` 1 с).

**Не нагружайте их сервер.** `vehicles` без `--route` делает около 18 запросов (104 маршрута по 6 за раз). Запускайте её не чаще раза в 30 секунд: их собственный сайт обновляется так же (`defInterval=30*1000` в `config.js`).

Пример вывода `vehicles` (одна машина):

```json
{"id": "1-3-1", "type": "bus", "route": "3", "marsh": "3", "graph": "1", "direction": "A",
 "lat": 55.0959, "lon": 82.9617, "recorded_at_utc": "2026-11-04T05:27:31Z", "recorded_at_local": "04.11 12:27:31",
 "azimuth": 197.0, "speed_kmh": 8.0, "segment_order": 25, "ramp": true, "accessibility": "yes",
 "state": "on_route", "on_line": true,
 "plan": [{"at_utc": "2026-11-04T05:39:00Z", "at_local": "12:39", "stop_name": "Ул. Учительская (Учительская)"}]}
```

Импорт как библиотеки (функции `parse_*` чистые, без сети):

```python
import json, nskgortrans as n
vehicles = n.parse_vehicles(json.load(open("samples/markers.json")))
low_floor = [v for v in vehicles if v.on_line and v.accessibility == "yes"]

c = n.Client()
bus3 = n.find_route(c.routes(), "3", "bus")
(trace,) = c.traces([bus3], "A")     # trace.stops по порядку движения
```

## Главное в пяти пунктах

1. **Низкий пол.** У каждой машины в `markers.php` есть поле `ramp`: `"1"` значит низкий пол или аппарель, `"0"` значит нет. Это единственный источник признака низкого пола на сайте.
2. **Пачки маршрутов.** Машины выдаются только по маршрутам, перечисленным в запросе, и **не больше 6 маршрутов за запрос**.
3. **Нет CORS.** Сервер не отдаёт заголовков `Access-Control-Allow-Origin` **[проверено]**, поэтому браузер (PWA) не может обращаться к нему напрямую. Нужен свой сервер-посредник (подробнее ниже).
4. **Прогноз без выхода.** Прогноз на остановке (`forecast.php`) не сообщает номер выхода машины. Поэтому из прогноза нельзя узнать, придёт ли низкопольная.
5. **Без документации.** Формат ответов никто не обещал сохранять. Разбор должен переживать странные записи, а признак доступности при любом сомнении должен быть `unknown`.

## Адреса сайта

Базовый адрес `https://map.nskgortrans.ru`. Авторизации нет. Все ответы JSON, и **почти все числа приходят строками**. Сервер ставит cookie `PHPSESSID`, она не нужна. Кэширование запрещено заголовком `Cache-Control: no-store`.

### Ключ маршрута (параметр `r`)

Формат `{тип}-{marsh}-{направление}-{name}|` **[проверено]**. Несколько ключей пишутся подряд: `1-3-W-3|3-0013-W-13|`.

- `тип`: 1 автобус, 2 троллейбус, 3 трамвай, 8 маршрутное такси. **В `listmarsh.php` это же число на 1 меньше**: 0, 1, 2, 7.
- `marsh`: внутренний код из `listmarsh.php`. Он не всегда совпадает с номером: у трамвая 13 это `0013`, у автобуса 5 это `005`.
- `направление`: `A` прямое, `B` обратное, `W` оба.
- `name`: номер для людей (`13`, `45К`).

Их сайт кодирует `r` дважды (`%257C`). Обычное кодирование (`%7C`) и `|` без кодирования тоже работают **[проверено]**. В утилите ключ строит функция `route_key()`.

### `GET /listmarsh.php?r=true`: все маршруты

```json
[{"type": 0, "ways": [{"marsh": "3", "name": "3", "stopb": "Вокзал \"Новосибирск-Главный\"", "stope": "Пос. Северный"}]}]
```

- `type` — вид транспорта (0 автобус, 1 троллейбус, 2 трамвай, 7 маршрутка).
- `stopb` и `stope` — конечные остановки. У кольцевых маршрутов `stope` пустой, а в `stopb` записан весь путь.
- На 2026-11-04 маршрутов 104. Список меняется редко, его можно кэшировать на сутки.

### `GET /markers.php?r=<ключи>`: машины сейчас

Главный адрес.

- **Не больше 6 маршрутов за запрос [проверено]:** при 8 и 12 ключах приходят машины только первых 6. Делите на пачки по 6.
- Пустой или неверный `r` даёт `{"markers":[]}`, без ошибки.
- Направление в ключе (`A` или `B`) отфильтровывает машины этого направления.

```json
{"markers": [{"title": "3", "id_typetr": "1", "marsh": "3", "graph": "1", "direction": "B",
  "lat": "55.052383422852", "lng": "82.947731018066", "time_nav": "27.10.26 17:33:09",
  "azimuth": "183", "speed": "14", "segment_order": "0", "ramp": "1",
  "rasp": "17:22+Плехановский ж/м (Кропоткина)|17:28+М. \"Гагаринская\"|"}]}
```

| Поле | Значение |
|---|---|
| `title` | номер маршрута для людей |
| `id_typetr` | вид транспорта (1, 2, 3, 8) |
| `marsh` | код маршрута |
| `graph` | номер выхода (наряда). Вид, маршрут и выход вместе дают устойчивый id машины на день: `1-3-1`. Отдельного бортового номера нет **[догадка: в ответах не видели]** |
| `direction` | `A` или `B` |
| `lat`, `lng` | координаты (строки). Нулевые (`0`,`0`) или вне допустимого диапазона отбрасывайте на всякий случай |
| `time_nav` | время GPS-отметки `ДД.ММ.ГГ ЧЧ:ММ:СС`, **местное время Новосибирска (UTC+7)**, без пояса. Функция `parse_time_nav()` переводит его в UTC |
| `azimuth` | курс в градусах от севера |
| `speed` | скорость, км/ч |
| `segment_order` | **[догадка, сверено по трассе]** сколько остановок своего направления машина уже проехала (±1). `0` значит на конечной или неизвестно |
| `ramp` | **`"1"`: низкий пол или аппарель; `"0"`: нет [проверено: по нему значок рисует их сайт]**. Неизвестно, что именно значит поле (низкий пол, аппарель или и то и другое) и обновляется ли оно, если аппарель сломалась. Это нужно спросить у ЦУГАЭТ. Безопасное правило: `"1"` → yes, `"0"` → no, всё остальное (нет поля, пусто, другое значение) → **unknown** |
| `rasp` | план машины на ближайших примерно 5 контрольных остановках в виде `ЧЧ:ММ+Название\|…`. Особые значения: `-` (плана нет), `Отстой`, `Идет на обед`, `Обеденный+перерыв\|` |

Особенности `rasp`:
- **Даты нет.** Для каждого времени берите момент, ближайший к `time_nav` в пределах ±12 ч (функция `nearest_moment()`). Тогда `00:07` после `23:55` попадёт на следующие сутки.
- **В плане бывают уже прошедшие времена** (например, 12:10 при отметке 12:35), а у стоящих машин план бывает устаревшим. Для прогноза прихода используйте его осторожно.
- Названия остановок записаны текстом, без id и координат. С названиями в `trasses.php` они совпадают не всегда дословно **[догадка]**.

**Какие машины их сайт скрывает.** Правило взято из функции `GoTransport` в `main.1.3.min.js` и повторено в `is_on_line()`:
- если `rasp` = `-`, машина скрыта, кроме маршруток и автобуса 24;
- машины в состоянии `Отстой`, `Идет на обед` или `Обеденный+перерыв|` скрыты всегда.

Дополнительно советуем отбрасывать машины с GPS-отметкой старше 5 минут: они, скорее всего, стоят в парке или потеряли связь.

Наблюдение 2026-11-04 (образец `samples/markers.json`, автобусы 3, 24 и трамвай 13): 36 машин, из них 32 на линии, у 24 `ramp=1`, у 12 `ramp=0`, `unknown` не было. На всём городе тогда было 422 низкопольные машины на линии.

### `GET /trasses.php?r=<ключи>`: линия маршрута и остановки

Ограничения в 6 маршрутов здесь нет: все 8 запрошенных пришли **[проверено]**.

```json
{"trasses": [{"r": [{"pc": "", "marsh": "3", "u": [
  {"id": "76", "n": "Вокзал \"Новосибирск-Главный\"", "len": "0", "lat": "55.03532", "lng": "82.89852"},
  {"lat": "55.03515", "lng": "82.89868"}]}]}]}
```

- `u` — точки линии по порядку движения.
- Точка, у которой есть `n` и `id`, — это остановка. `id` нужен для `forecast.php`. Точки с `n` = `-` остановками не считайте.
- **Чтобы получить порядок остановок, запрашивайте `A` и `B` отдельно.** `W` склеивает оба направления: у автобуса 3 в A 35 остановок, в B 34, в W 69.
- `len` во всех увиденных ответах равен `"0"`, `pc` всегда пустой.
- Линия меняется редко, её можно кэшировать на сутки.

### `GET /forecast.php?id=<id остановки>&type=platform`: прогноз на остановке

```json
{"routes": [{"id_marsh": "39", "title": "23", "marsh": "23", "typetr": "2", "direction": "A",
  "markers": [{"id": "39", "time": 0}, {"id": "39", "time": 4}], "stop_end": "Вокзал \"Новосибирск-Главный\""}]}
```

- `time` — минуты до прибытия. **Здесь это число, а не строка.**
- Как это показывает их сайт: `0` пропускает, дальше 30 минут не показывает, меньше 3 минут пишет «прибытие».
- **Номера выхода (`graph`) в ответе нет**, а `markers[].id` — это id маршрута, а не машины. Поэтому по прогнозу нельзя узнать, низкопольная ли машина.
- Неизвестная остановка даёт `{"routes":[]}`.

Если нужно узнать, когда придёт **низкопольная** машина, считайте сами:
1. возьмите низкопольные машины маршрута из `markers.php`;
2. по `direction` и `segment_order` найдите тех, кто ещё не проехал вашу остановку по порядку из `trasses.php`;
3. время оцените по `rasp`, если там есть эта остановка, или по расстоянию вдоль линии.

Это наш вывод, ЦУГАЭТ его не проверял.

## Советы для PWA

1. **Нужен посредник.** CORS нет, поэтому браузер не прочитает ответы `map.nskgortrans.ru`. Варианты:
   - свой маленький сервер (FastAPI, Node, Cloudflare Worker и т. п.): он раз в 30 секунд забирает машины, держит их в памяти и отдаёт PWA уже разобранными, только низкопольные;
   - одна загрузка на всех пользователей, а не на каждого: так их сервер получает одинаковую нагрузку при любом числе пользователей. Это важно и для вежливости, и для разрешения ЦУГАЭТ.
   - Публичные CORS-прокси не используйте: они ненадёжны и видят трафик.
2. **Кэш:**
   - маршруты и линии храните сутки;
   - машины обновляйте раз в 30 секунд;
   - при сбое сайта отдавайте прошлый снимок с пометкой времени («данные от 12:31»), а не пустую карту.
3. **Service worker:** маршруты и линии можно класть в кэш для работы без сети. Позиции машин кэшировать нельзя. Если сети нет, покажите «нет сети» и время последних данных.
4. **Доступность в три состояния:** `yes`, `no`, `unknown`. Никогда не показывайте `unknown` как `yes`. Пустой или странный `ramp` даёт `unknown`.
5. **Время:**
   - `time_nav` переводите в UTC сразу при разборе;
   - пользователю показывайте время по Новосибирску;
   - не полагайтесь на часовой пояс телефона пользователя.
6. **Обновление в фоне:** когда вкладка скрыта (`document.visibilityState === "hidden"`), останавливайте запросы позиций.

Разбор того же ответа на TypeScript:

```ts
type Accessibility = "yes" | "no" | "unknown";
const rampToAccessibility = (ramp: unknown): Accessibility =>
  ramp === "1" ? "yes" : ramp === "0" ? "no" : "unknown";

// "27.10.26 17:33:09" (Новосибирск, UTC+7) -> Date (UTC)
function parseTimeNav(s: string): Date | null {
  const m = /^(\d{2})\.(\d{2})\.(\d{2}) (\d{2}):(\d{2}):(\d{2})$/.exec(s);
  if (!m) return null;
  const [, d, mo, y, h, mi, se] = m.map(Number);
  return new Date(Date.UTC(2000 + y, mo - 1, d, h - 7, mi, se));
}

const routeKey = (typeCode: 1 | 2 | 3 | 8, marsh: string, name: string, dir: "A" | "B" | "W" = "W") =>
  `${typeCode}-${marsh}-${dir}-${name}|`;
```

## Как проверить, что всё ещё работает

1. Запустите `python3 nskgortrans.py check`. Если в ответе `"ok": true`, все четыре адреса отвечают в ожидаемом формате.
2. Если что-то сломалось, выполните `python3 nskgortrans.py snapshot --out fresh/` и сравните `fresh/` с `samples/`.
3. Поправьте разбор **через тест**: сначала тест на новом образце, потом код.
4. Чтобы в своём проекте не ломать тесты из-за сети, держите сетевые тесты отдельно от обычных и запускайте их вручную.
