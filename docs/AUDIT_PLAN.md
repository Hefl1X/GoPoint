# GoPoint: обновлённая архитектура и план внедрения (по аудиту `bagi.md`)

## Контекст

Владелец провёл аудит (`bagi.md`) после MVP (запросы 0–9). Проблемы: нет прямого пути пешком А→Б,
ложное «Транспорта сейчас нет», режим коляски в пеших участках, слабый поиск (НГУ, вокзал),
нет остановок на карте, машины «прыгают», виды транспорта неразличимы, нет панорам, один вариант маршрута.

Сверка аудита с кодом и замерами (честно, для владельца):
- **Подтверждено:** нет пути пешком А→Б в поиске (уже начато в ветке `feat/route-variants`); вариант
  молча отбрасывается, если пешая пересадка по улицам дольше оценки (`journey_planner.py:_journey`,
  `return None`); 20 ближайших остановок на узлах могут оказаться одного направления; остановок на карте
  нет; машины переставляются рывком; в значке машины нет вида транспорта; в карточке машины остановки
  не нажимаются; один вариант на экране.
- **Не подтверждено замером:** «ramp пуст у 70–80 % машин» — по замеру 04.11 низкопольных 61 %
  (автобусы 67 %, троллейбусы 89 %, трамваи 75 %, маршрутки 2 %), `unknown` ни одного.
  «Режим коляски блокирует 95 % перекрёстков» — в проверке 10 маршрутов путь для коляски отличался от
  пешеходного не больше чем на 168 м, отказ один (середина пл. Ленина). «Не находит Оперный, Ауру,
  Галерею, Зоопарк» — по замеру находит (27 из 30). Реальные промахи: «вокзал», «НГУ», «больница 1».
- Ложное «нет транспорта» на Вокзал → пл. Ленина пока не воспроизведено: сначала запись живого снимка
  и тест, потом исправление (правило «баг: сначала тест»).

**Решения владельца (14.11.2026, в этой сессии):**
1. Режим коляски для пеших участков **убрать полностью**: обычный пешеход OTP, путь строится всегда.
2. Нет низкопольных — **как сейчас**: «Транспорта сейчас нет» + ссылка «Показать любой транспорт».
3. Панорамы — **ссылка на Яндекс Карты** по координатам остановки.
4. Карточка «Пешком» рядом с транспортом — **всегда, если путь до 2 км**.

## Обновлённая архитектура (что меняется)

### Сервер
1. **Пешие участки (`WalkPlanner`, `adapters/otp`).** Запрос OTP без `accessibility.wheelchair`,
   `otp/router-config.json` без `wheelchairAccessibility`. Убрать `NoAccessibleWalkError` и повторный
   запрос «для пешехода» (`adapters/otp/walk.py`), ошибку из `ports`, API и текстов сайта.
   Скорость остаётся настройкой `GOPOINT_WALK_SPEED_MPS` = 0,8 м/с (подтверждена владельцем 04.11;
   это скорость, а не режим — сказать владельцу в отчёте, что её можно поменять).
   Признак `hasStairs` остаётся как **сведение** («на пути есть ступени»), не как фильтр — правило честности.
2. **Поиск маршрута (`LiveTransit`).**
   - *Путь пешком как полноценный кандидат.* `JourneyPlanner.plan` уже считает `_direct_walk`. Добавить:
     правило показа «≤ 2 км» (`GOPOINT_WALK_OPTION_MAX_M=2000`, вместо `walk_option_extra/max`);
     отбрасывать варианты на транспорте, которые приезжают **позже** пути пешком или в которых пешком
     **больше**, чем весь путь пешком (убирает «4 км по кольцу на другую сторону улицы»). Чистая функция
     в `domain/journey_search.py` (`drop_dominated_by_walk`), тесты вперёд.
   - *Остановки у точек А и Б.* Вместо «20 ближайших» — `domain/access.py`: для каждого маршрута и
     направления ближайшая его остановка в радиусе `GOPOINT_ACCESS_RADIUS_M` (1500 м), плюс не меньше
     `K` ближайших вообще; потолок `GOPOINT_ACCESS_STOPS_MAX` (40). Так на узле попадают оба направления.
     Ответы OTP кэшируются, как сейчас.
   - *Пересадка не успевает → искать заново.* В `_journey` вместо `return None` запоминать настоящее
     время пересадки (словарь поправок `transfer_overrides`) и перезапускать `search` (не больше 2 раз).
     Это закрывает пункт BACKLOG про отброшенные варианты.
   - *Воспроизведение «нет транспорта».* Инструмент `server/tools/record_snapshot.py` (сохраняет живой
     снимок машин и линий в `server/tests/fixtures/live/…`), тест на сохранённом снимке для
     Вокзал → пл. Ленина; по нему находим настоящую причину.
   - Варианты «быстрее / меньше пересадок / меньше пешком» уже сделаны на сервере (коммит `2405a74`).
3. **Поиск адресов (`Geocoder`).** Новый слой перед Photon, без смены сервиса:
   - `adapters/local_places/`: список синонимов `data/geocoder/aliases_nsk.csv` (НГУ, вокзал → Новосибирск-
     Главный, номера больниц и т. п.: короткое имя, полное, точка, вид) — правим файл, не код;
   - остановки ЦУГАЭТ (1618 уникальных, уже есть в `LiveSnapshotService.network`) как подсказки вида «ост.»;
   - `services/geocoding.py` объединяет: точное совпадение синонима первым, затем остановки и Photon,
     повторы в пределах 150 м убираются (`domain/search.py` уже это умеет). Порт `Geocoder` не меняется:
     составной геокодер собирается в `main.py`.
4. **Новый адрес API** `GET /api/v1/live/stops?bbox=` — остановки (id, название, точка, виды транспорта)
   для слоя карты; из уже загруженных линий, без новых запросов к ЦУГАЭТ; кэш на сутки. Линии всех
   маршрутов грузить сразу при первом обращении к сайту (снимает 25 с ожидания первого маршрута).
5. Удалить из `server/app/domain/models.py`/`schemas.py` поля и статусы, которые были только для
   режима коляски; обновить OpenAPI и типы сайта (`openapi_export`, `npm run api:types`).

### Сайт
1. **Варианты маршрута** — довести незакоммиченную ветку (`RoutePanel.tsx`, `journey.ts`): до 3 карточек
   с ярлыками и карточка «Пешком».
2. **Слой остановок** (`MapView`): новый проп `stops` и `onStopSelect`; в `adapters/maplibre` источник
   `stops`, кружок с обводкой от zoom 15, подпись от 16; нажатие → `#/stop/{id}`; в режиме «Выбрать на
   карте» не нажимаются. В `adapters/map-list` — пропустить (там список машин). Данные — новый метод
   `LiveApi.stops(bbox)` (zod), запрос при остановке карты, справочник «сначала сеть» в service worker.
3. **Вид транспорта в значке машины** (`drawPill`): маленький знак вида слева от номера (автобус,
   троллейбус, трамвай, маршрутка) + по-прежнему цвет; низкопольная — заливка, остальные — контур
   (форма, а не только цвет). Пояснение «Как отличить на карте» в «Настройках» обновить.
4. **Плавное движение машин.** При новом снимке — переход от старой точки к новой за ~1,5 с
   (`requestAnimationFrame`, только машины в видимой области, до 300 шт.). **Без угадывания вперёд**:
   показывать только реально присланные положения (честность). При `prefers-reduced-motion` — без анимации.
5. **Карточка машины** (`VehicleCard.tsx`): каждая остановка «Дальше по маршруту» — ссылка `#/stop/{id}`.
6. **Панорама остановки** (`LiveStopScreen.tsx`): кнопка-ссылка «Посмотреть остановку на панораме»
   (открывается Яндекс Карты, новая вкладка). Построение ссылки — порт `StreetImagery` +
   `adapters/yandex-panorama/` (формат ссылки проверить по документации Яндекса
   «yandex.ru/dev/yandex-apps-launch/maps», записать в DECISIONS; если панорамы в точке нет, Яндекс
   покажет карту — сказать об этом владельцу). Замена на Panoramax позже — только адаптер.
   Тексты в `ru.ts`: подпись кнопки и пояснение «снимок может быть старым» (текст — на утверждение
   владельцу в отчёте).
7. Убрать тексты и состояние ошибки `NO_ACCESSIBLE_WALK` (`RoutePanel`, `ru.ts`, тесты).
