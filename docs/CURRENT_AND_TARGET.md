# GoPoint — текущее и целевое состояние

Итог обсуждения на 21 ноября 2026 года. Продуктовый код шага 04 ещё не менялся. Основной план реализации, параметры и критерии приёмки для GPT Sol — [ROUTING.md](ROUTING.md); точка продолжения — [ROADMAP.md](ROADMAP.md). Эта таблица не заменяет подробный план.

| Возможность | Сейчас в коде | Цель шага 04 |
|---|---|---|
| Базовое расписание | Приложение получает линии, остановки и GPS; загрузчик полного расписания пока отсутствует. Сохранены проверочные HTTP-ответы ЦУГАЭТ. | Код получает полные таблицы `grasp.php?s=0`, связывает остановки/рейсы/календарь и формирует GTFS. Время хранится для каждого рейса на каждой остановке: у №13 оно меняется, у №35 есть конфликт остановок. Факты — [SCHEDULE.md](../data/tsugaet/SCHEDULE.md). |
| Обновление расписания | Есть только разовые образцы для тестов. | Проверка источника раз в сутки в 03:00 по Новосибирску; без изменений не создавать новый GTFS/граф. Полный городской сбор и регулярный запуск — после согласования объёма. |
| Общее и низкопольное представления | Фильтр применяется к видимым машинам. Поиск зависит от текущего GPS. | Одна общая база и один расчёт GPS-прогноза. Low — выборка рейсов с уверенно назначенной свежей машиной `ramp=1`; без подтверждения рейс доступен только в общем режиме по пригодному расписанию. Низкий пол всей линии по одной машине не выводится. |
| Быстрые обновления | Один GPS-опрос для всех, не чаще 30 с при активности. | Сохранить этот опрос. После снимка обновлять прогнозы обоих режимов и low-допуск, также обрабатывать истечение подтверждений. OTP читает готовый GTFS-Realtime каждые 10 с внутри Docker. Это не сборка графа и не дополнительные обращения к ЦУГАЭТ. |
| Подготовка OTP | Есть уличный граф для ходьбы; `transitFeeds` и `updaters` пусты. Скрипт делает общую сборку. | Один OTP: сначала сохранить уличную часть, затем добавить два логических GTFS-фида. При изменении только транспорта повторно использовать уличную часть; остановки связываются с улицами при транспортной сборке. GPS не меняет базовый граф. Механизм двух фидов доказать экспериментом. |
| Среда запуска и ресурсы | Docker-демо на Mac; есть одиночный замер стека с уличным OTP, транспортный граф ещё не измерен. | Сначала качественный сайт и стабильная работа полного стека в Docker на Mac, без лимита 4 ГБ. Сборка/импорт выполняются локально отдельными командами. Замерить память/CPU/диск, сборку, старт и задержки готового приложения; сервер выбрать после этого. Его подбор не блокирует шаг 04. |
| Построение пути | `JourneyPlanner`/`LiveTransit` ищет транспорт и пересадки по машинам; OTP считает пешие части. Следующий выезд с конечной может потеряться. | OTP выбирает всю поездку по расписанию и поправкам: ходьба, ожидание, транспорт, пересадки. В общем режиме отсутствие GPS не блокирует плановый поиск. Подходящие отправления и выполнимые пересадки всё равно необходимы — наличие линии не гарантирует поездку в любое время. |
| Конечная и пропавшая машина | Один `is_usable` применяется к карте и поиску; отстой/отсутствие `rasp` могут скрыть машину. Поиск рассматривает только оставшиеся остановки. | Разделить наблюдение, состояние, назначение рейса, прогноз, low-допуск и видимость. Нормальная стоянка со свежим GPS не отменяет подтверждённое назначение; завершённый рейс не назначает машину следующему автоматически. План общего режима не отменяется по потере маркера. |
| Проверка выбранной поездки | `/route/check` закрепляет первую машину и может пропустить замену второй. | Проверять всю цепочку рейсов, дату обслуживания, последовательности посадки/высадки и версию расписания. Изменение пересадки требует явного сообщения; пассажир не считается автоматически севшим. |
| Выбор режима | По умолчанию весь транспорт, ключ `gopoint.lowFloorOnly.v2`. | По умолчанию низкопольный режим с ключом v3; все посадки подтверждены. Новый default включается вместе с готовым low-потоком. «Весь транспорт» использует общую базу и может показывать плановое время без машины. |
| Карта и панорамы | Подложка OSM, маркеры перемещаются за 1,5 с между опросами. Панорама иногда открывается в стороне от площадки. | Сохранить карту и действующие live-функции. Плавность движения и точность панорам — отдельные шаги 05/06, не расширять ими шаг 04. |
| Поиск адресов | Свои названия, остановки и Photon; точный дом/населённый пункт иногда находятся неверно. | Шаг 03 отложен до ядра маршрутизации; не включать его переделку в миграцию OTP. |

**Контрольная поездка:** «Цветной проезд → Речной вокзал», №8 и №35. После ухода предыдущей машины общий режим рассматривает следующий плановый рейс. Сначала разрешить конфликт остановок №35. Дополнительная приёмка — низкопольные машины на каждой посадке с пересадкой, отказ GPS, стоянка на конечной и переход суток.

**Старт Sol:** этап 1 подробного плана — чистый parser полных таблиц и модель расписания на сохранённых данных, без нового сетевого сбора. Фактическое покрытие города и точность назначения GPS пока не доказаны, ресурсные потребности полного транспортного стека ещё не измерены; соответствующие проверки перечислены в §10 плана.
